## 2. 优化步骤与贡献分解

| 步骤 | 改动内容 | 核心技术假设与收益 | 贡献度 |
| :---: | :--- | :--- | :--- |
| **1** | **首屏注入真实 Initial Data** | 消除客户端在首屏挂载后向 `/api/douban` 发送的 6 路并发 HTTP 往返请求；通过预置精选榜单配合 `staleTime: 600000`，首屏第 0 毫秒即有卡片呈现 | 贡献 **~350ms** |
| **2** | **重型弹窗/抽屉组件动态拆包** | 将详情弹窗 `DetailModal`、源管理器 `SourceManagerDrawer`、播放历史 `HistoryPanel` 改为 `next/dynamic` 异步懒加载，首屏 First Load JS 从 243KB 降至 228KB | 贡献 **~120ms** |
| **3** | **切断首屏冗余 Refetch** | 显式配置 `refetchOnMount: false` 和 `refetchOnWindowFocus: false`，防止 TanStack Query 在首屏瞬间向豆瓣发起重复查询，彻底杜绝 429 封禁与页面等待 | 稳定性提升至 **100%** |
| **4** | **Hero 壁纸与卡片分级加载** | 4K 原生焦点大片壁纸声明 `priority`（`fetchpriority="high"`、`loading="eager"`）；横向滚动行仅前 4 张卡片 eager，第 5 张起全量 `loading="lazy"` | 贡献 **~60ms**，LCP 降至 1.2s |

## 3. 上线清单与回滚预案

- **涉及修改的代码文件**：
  1. `src/lib/initial-douban.ts`（新增首屏精选真实影视数据）
  2. `src/components/douban-section.tsx`（绑定 initialData 与首屏防抖选项）
  3. `src/components/header.tsx`（源管理与历史抽屉 dynamic 异步化）
  4. `src/app/page.tsx`（DetailModal dynamic 异步化）
  5. `src/components/smart-image.tsx`（支持 priority 与 fetchpriority="high"）
  6. `src/components/netflix-hero.tsx`（Hero 4K 原生壁纸 priority 优化）
  7. `src/components/netflix-row.tsx`（卡片 index < 4 分级 eager/lazy）
- **性能资产目录**：`perf/`（已建立完整的基线、测速脚本、实验日志与棘轮规则）
- **回滚预案**：
  - 本次改动纯属前端渲染性能调优，未触及任何底层数据库与 API 结构；
  - 若线上出现任何预期外问题，可通过 `git revert HEAD` 并在 60 秒内触发 Vercel 自动回滚。
